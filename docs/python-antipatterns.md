## 1. Архитектура и импорты

- **Исправление только одного вызывающего места.** Найти всех вызывающих общий код; устранить причину в общей точке и проверить затронутые пути.
- **Повторная реализация существующего решения.** Сначала использовать проектный helper, затем stdlib или установленную библиотеку. Не добавлять зависимость ради нескольких простых строк.
- **Фабрики, плагины, базовые классы и универсальные конфиги без потребителя.** Оставлять прямую функцию/класс; выделять абстракцию при реальном повторении поведения.
- **Модуль, совмещающий HTTP, SQL, браузер и платежную политику.** Сохранять существующие границы: адаптер извлекает ответ, репозиторий хранит, сервер решает права и стоимость.
- **Новый тяжёлый побочный эффект при импорте.** Не запускать скан, поток, сетевой запрос или миграцию просто через `import`; использовать явную инициализацию и существующий lifecycle. Не ломать текущую настройку путей без отдельной задачи.
- **Циклические и wildcard-импорты, затенение stdlib.** Явные импорты; не создавать `json.py`, `typing.py` или `httpx.py`, перекрывающие библиотеку. Исправлять зависимость, не маскировать её случайным порядком импортов.
- **Изменение `sys.path`, рабочего каталога или глобальный monkeypatch ради штатной работы.** Использовать пакетные импорты и явные пути; ограниченный workaround документировать и проверять в source/frozen режиме.
- **Магия вместо читаемого управления потоком.** Не уплотнять ветвления, обработку ошибок и побочные эффекты в вложенные тернарные выражения, comprehensions или динамический `getattr` из пользовательской строки.

Основание: [PEP 8](https://peps.python.org/pep-0008/),
[Python FAQ: imports](https://docs.python.org/3.12/faq/programming.html#what-are-the-best-practices-for-using-import-in-a-module).
Границы модулей и минимальность изменений — правила этого проекта.

## 2. Изменяемое состояние и семантика языка

- **`def f(items=[])`, `cache={}` или готовый объект по умолчанию.** Для отдельного состояния создавать объект внутри при `is None`; для dataclass использовать `field(default_factory=...)`.
- **Вычисление времени, UUID или вызов функции в значении аргумента по умолчанию.** Значение фиксируется при определении функции; получать его при вызове, если оно должно быть свежим.
- **Общий mutable-атрибут класса вместо состояния экземпляра.** Инициализировать экземпляр отдельно; намеренное общее состояние должно иметь владельца и синхронизацию.
- **`[[0] * width] * height` и `dict.fromkeys(keys, [])`.** Они разделяют вложенные объекты; создавать независимые строки/значения comprehension-ом.
- **Присваивание или shallow copy как глубокая копия.** Учитывать общие вложенные объекты; копировать только необходимый уровень, не добавлять `deepcopy` автоматически.
- **Callback/lambda в цикле захватывает меняющуюся переменную.** Зафиксировать нужное значение аргументом по умолчанию или `functools.partial`; проверить разные итерации.
- **`is` для сравнения строк, чисел или UUID.** Использовать `==`; `is` оставлять для идентичности, `None` и явного sentinel.
- **`value or default` и `if value` при различении отсутствия и пустоты.** Проверять `is None` или наличие ключа; сохранять допустимые `0`, `False`, пустую строку и список.
- **Изменение коллекции во время обхода.** Строить результат отдельно либо обходить снимок, если удаление/добавление иначе меняет итерацию.
- **Усечение пар через обычный `zip`, повторное чтение исчерпанного iterator.** При требовании равных длин использовать `zip(..., strict=True)`; генератор считать одноразовым, материализовать лишь при необходимости.
- **Результат `list.sort()`/`append()` принят за список, либо `dict.get(key, expensive())` за ленивый fallback.** Мутации возвращают `None`, аргументы вычисляются заранее; отделять изменение и выбор значения.
- **Затенение `list`, `dict`, `id`, `type`, `open`, либо путаница локальной/global-переменной.** Давать предметные имена и явно передавать состояние вместо скрытой зависимости.

Основание: [Python FAQ: default arguments, closures, copying](https://docs.python.org/3.12/faq/programming.html#why-are-default-values-shared-between-objects),
[dataclasses](https://docs.python.org/3.12/library/dataclasses.html#default-factory-functions),
[built-in types](https://docs.python.org/3.12/library/stdtypes.html),
[built-in functions: zip](https://docs.python.org/3.12/library/functions.html#zip),
[execution model](https://docs.python.org/3.12/reference/executionmodel.html).

## 3. Числа, время, текст и сериализация

- **`float` для денежных расчётов.** В AIRate хранить и считать целые копейки; при внешнем десятичном формате использовать `Decimal` из строки с явным округлением, затем проверенное преобразование.
- **Неявное округление, `Decimal(float)`, допуск `NaN`/бесконечности.** Проверять конечность, диапазон и допустимое число десятичных знаков; не исправлять неверную цену молчаливым округлением.
- **`bool` проходит как произвольный `int`.** Для ID, количества и копеек валидировать тип/диапазон по контракту; строгая проверка нужна там, где `True` недопустим как `1`.
- **Смешение naive и aware datetime, локальное время без зоны.** Для новых внешних timestamps использовать UTC с зоной; текущий DB-контракт менять только с проверенной совместимостью, не одной заменой `utcnow()`.
- **`replace(tzinfo=...)` как конвертация зоны, wall clock для дедлайна.** Переводить зону через `astimezone`; интервалы и дедлайны считать `time.monotonic()`/`perf_counter()`, не календарными часами.
- **Неявная системная кодировка и молчаливое `errors='ignore'`.** Для своих текстовых файлов задавать UTF-8; BOM/кодировку внешних данных обрабатывать явно, не терять содержимое.
- **`strip('.json')` как удаление суффикса, `str(bytes)` как декодирование.** Использовать `removesuffix`/`removeprefix`, `Path.suffix` и явный `decode`; `strip` удаляет набор символов.
- **Regex или `split` как универсальный JSON/HTML/URL-парсер.** Использовать stdlib/существующий parser; при fuzzy/Unicode-нормализации сохранять исходный ответ и не нормализовать секреты.
- **JSON считается безопасным без ограничений и схемы.** Ограничивать входной размер и сложность, проверять обязательные поля, типы и допустимые числа; не скрывать несовместимость через `default=str`.

[monotonic clocks](https://docs.python.org/3.12/library/time.html#time.monotonic),

## 4. Исключения и достоверность результата

- **`except:`, перехват `BaseException` или широкий `try` вокруг всего алгоритма.** Ловить ожидаемые исключения на узкой операции; широкий `Exception` допустим на внешней границе с честным состоянием ошибки и диагностикой.
- **`except Exception: pass` и возврат пустого ответа при сбое.** Отличать отсутствие данных от ошибки; записывать причину и возвращать корректный failure, не успешный пустой скан.
- **`return`, `break`, `continue` в `finally`.** Они могут подавить исключение или прежний результат; `finally` использовать для cleanup.
- **Повторный `raise exc` или замена ошибки без причины.** Для проброса использовать `raise`, для преобразования — `raise DomainError(...) from exc`; наружу не отдавать секретные детали.
- **`assert` для авторизации, пользовательского ввода и проверки записи.** Оптимизированный Python удаляет assert; делать явную проверку и исключение/ошибку API. Assert допустим в тестах и диагностических self-check.
- **Неоднозначный контракт «возвращает bool, None, dict или Exception».** Сохранять существующий понятный контракт и явные типы успеха/ошибки, не превращать исключения в произвольные значения.
- **Cleanup маскирует исходную ошибку.** Сохранять основную причину; вторичную ошибку закрытия диагностировать отдельно и не объявлять операцию успешной.
- **Безусловный retry после любого exception.** Разделять ошибку ввода, прав, тарифа, провайдера и транспорта; повторять только применимые временные ошибки в рамках политики разделов 9–10.

Основание: [PEP 8: exceptions](https://peps.python.org/pep-0008/#programming-recommendations),
[exceptions](https://docs.python.org/3.12/library/exceptions.html),
[Ruff B012](https://docs.astral.sh/ruff/rules/jump-statement-in-finally/),
[optimization and assert](https://docs.python.org/3.12/library/functions.html#compile).

## 5. Владение ресурсами и журналирование

- **Закрытие файлов/клиентов только на счастливом пути.** Использовать `with`/`async with` или `try/finally`; владелец ресурса отвечает за закрытие при exception/cancel.
- **Надежда на GC, `__del__`, `atexit` или daemon thread для важной записи.** Явно завершать работу; аварийное отключение учитывать сохранённым состоянием и восстановлением.
- **Незакрытый streaming response, курсор, S3 body, page/context.** Закрывать и при раннем выходе; потоковое чтение должно иметь лимит.
- **Новый HTTP client/session на каждую итерацию.** Переиспользовать в пределах подходящего lifecycle; не переносить async-клиент между разными event loop.
- **`print` вместо рабочей диагностики, настройка root logger при каждом импорте.** Использовать проектное журналирование, logger модуля и централизованную настройку.
- **Потеря traceback либо дублирование одной ошибки на каждом уровне.** Логировать в ответственном месте через `logger.exception`/`exc_info`, с run/check ID и этапом, соблюдая редактирование секретов.
- **Токены, cookies, пароль, полный Authorization/URL или ответы пользователя в логах.** Убирать секреты и чувствительные данные; ограничивать размер и срок хранения диагностических файлов.
- **Неограниченные логи и дорогая интерполяция выключенного debug.** Ограничивать объём, использовать параметры logger; дорогое вычисление guard-ить уровнем, sanitise перевод строки в недоверенном поле.

Основание: [logging](https://docs.python.org/3.12/library/logging.html),
[OWASP logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html),
[HTTPX clients](https://www.python-httpx.org/advanced/clients/),
[HTTPX async streaming](https://www.python-httpx.org/async/#streaming-responses).

## 6. Async, потоки, процессы и остановка

- **`time.sleep`, sync HTTP/SQL/S3 или тяжёлый CPU-код внутри async/UI-потока.** Await-ить async API либо выполнять блокирующую операцию через существующий worker/`to_thread`; CPU-нагрузку выбирать по измерению, не плодить процессы автоматически.
- **Уверенность, что любой `def` FastAPI автоматически отправит в thread pool.** Это относится к вызываемым фреймворком sync endpoints/dependencies; напрямую вызванный helper выполняется в текущем потоке.
- **Coroutine создана, но не await-нута; task создана без владельца.** Await-ить результат или хранить задачу, получать её исключение и закрывать при shutdown; fire-and-forget требует явного lifecycle.
- **`gather()` считается автоматической отменой соседей при первой ошибке.** Учитывать его реальную семантику; при требовании общего прекращения использовать подходящий `TaskGroup` или существующую отмену с ожиданием завершения.
- **`CancelledError` проглочен; после отмены задача продолжает списание/запись.** Выполнить cleanup и повторно поднять отмену; ограниченное защищённое завершение допустимо лишь по обоснованному контракту целостности.
- **Нет общего дедлайна или cancellation означает немедленную остановку.** Учитывать cleanup, `wait_for` и уже начатую внешнюю операцию; timeout ожидания `to_thread` не останавливает поток.
- **`asyncio.run()` внутри работающего loop, объект loop используется из другого потока.** Соблюдать владельца loop; для передачи работы использовать thread-safe scheduling API и существующий мост.
- **Безлимитные `create_task`/`gather`, очереди и executors.** Ограничивать параллелизм и backlog; один semaphore без ограничения числа созданных задач не ограничивает память.
- **Синхронный Lock удерживается через `await`, ожидание сети под lock.** Выбирать lock для соответствующей модели, делать критическую секцию короткой; учитывать порядок нескольких locks.
- **GIL принят за защиту составной операции или process-global lock за межпроцессную блокировку.** Для общей памяти использовать lock/queue, для DB-инварианта — транзакцию/constraint; учитывать несколько workers.
- **Потоки считаются гарантированным ускорением CPU-кода.** В Python 3.12 типичный Python CPU-код ограничен GIL; профилировать, учитывать исключения библиотек, освобождающих GIL.
- **Рабочий поток напрямую меняет GUI; daemon shutdown теряет работу.** Использовать механизм UI-framework, сигнал остановки и управляемое завершение; критический результат сохранять до выхода.
- **Multiprocessing запускается при импорте на Windows.** Защитить entry point `if __name__ == '__main__'`, использовать нужный frozen `freeze_support`; не передавать открытый DB/browser/client как универсально сериализуемое состояние.

Основание: [asyncio development](https://docs.python.org/3.12/library/asyncio-dev.html),
[tasks, cancellation, TaskGroup, threads](https://docs.python.org/3.12/library/asyncio-task.html),
[threading](https://docs.python.org/3.12/library/threading.html),
[multiprocessing](https://docs.python.org/3.12/library/multiprocessing.html),
[FastAPI sync/async](https://fastapi.tiangolo.com/async/).

## 7. FastAPI, схемы и конфигурация

- **Аннотация типа принята за runtime-валидацию.** Проверять вход через существующие Pydantic-схемы и бизнес-условия; внутренний `cast` ничего не проверяет.
- **Неожиданная coercion (`'1'`, `True`, пустые значения).** Задавать strict/constraints для конкретных опасных полей; не включать глобально новый режим без проверки совместимости агентов.
- **Недоверенные данные переданы в `model_construct`, `model_copy(update=...)` или setattr/dict-update модели.** Эти обходы не заменяют валидацию; валидировать изменяемые значения и разрешённые поля.
- **Mass assignment: `**payload` меняет owner, роль, баланс или статус.** Использовать явную write-схему/allowlist; запрет неизвестных полей вводить там, где позволяет контракт.
- **ORM-объект или внутренняя модель возвращена целиком.** Использовать явный публичный response contract; не раскрывать password hash, device token, storage key или приватные настройки.
- **Ошибка названа HTTP 200, `detail=str(exc)` раскрывает внутренности.** Сохранять семантику ошибок, безопасное сообщение и корреляцию с серверной диагностикой.
- **`BackgroundTasks` используется как надёжная очередь платежей/результатов.** Это работа в процессе приложения; для восстановления использовать существующий persisted outbox/state, не объявлять гарантированную доставку.
- **Ресурс запроса передан в фон после закрытия dependency, lifespan смешан с устаревшими events.** У фоновой задачи должен быть свой scope; выбирать существующий lifecycle и проверять startup/shutdown, не переписывать его ради стиля.
- **Настройка читается по-разному в каждом модуле, отсутствие секрета заменено небезопасным default.** Переиспользовать конфигурацию, проверять обязательные значения на старте; не менять окружение процесса во время запроса.

Основание: [Pydantic 2.10 models](https://docs.pydantic.dev/2.10/concepts/models/),
[strict mode](https://docs.pydantic.dev/latest/concepts/strict_mode/),
[type hints](https://docs.python.org/3.12/library/typing.html),
[FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/),
[BackgroundTasks](https://fastapi.tiangolo.com/tutorial/background-tasks/),
[REST security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html).

## 8. SQLite, PostgreSQL, ORM и миграции

- **SQL собирается из пользовательских строк.** Значения передавать параметрами/ORM; динамические имена таблиц, колонок и сортировку выбирать из allowlist, параметр значения их не заменяет.
- **Общая SQLAlchemy Session между потоками или concurrent tasks.** Session принадлежит одному потоку/операции, AsyncSession — одной задаче; engine/pool и Session имеют разный lifecycle.
- **SQLite connection перенесён между потоками, `check_same_thread=False` назван исправлением.** Сохранять thread-local модель `app/db/repo.py`; отключение проверки не сериализует запись.
- **SQLite `with connection` считается закрытием или открытием транзакции.** Контекст управляет commit/rollback при подходящем режиме; close и границы транзакции задаются отдельно. Учитывать текущий `isolation_level=None` и явный BEGIN.
- **Частичные commit в середине бизнес-операции; продолжение после неудачного flush.** Задать границу транзакции, откатить ошибку; SQLAlchemy Session после failed flush требует rollback перед повторным использованием.
- **Сеть, LLM или ожидание пользователя при открытой write transaction.** Разделять этапы и проверять актуальность при короткой записи; не удерживать lock ради удалённого вызова.
- **Check-then-insert/update защищён только Python-проверкой.** Инварианты выразить UNIQUE/FK/CHECK и атомарным update/row lock по модели; обрабатывать конфликт и гонку, не только последовательный тест.
- **Скрытый N+1 и ленивое ORM-чтение вне session.** Загружать необходимые данные подходящим eager/batch-путём; не загружать все связи автоматически.
- **Полный fetchall всех отчётов, пагинация без стабильного ORDER BY.** Ограничивать выборку и обеспечивать порядок; стратегия пагинации должна учитывать размер и изменения данных.
- **FK/каскады считаются одинаковыми в SQLite и PostgreSQL.** Сохранять `PRAGMA foreign_keys` и проверки целостности; изменения критичных SQL-путей проверять на соответствующей СУБД.
- **Autogenerate-миграция принята без чтения; `create_all` заменяет migration.** Проверять SQL, backfill, nullability, rename/drop и совместимость предыдущего приложения; сохранять delivery backup/restore gates.
- **Живая SQLite скопирована одним DB-файлом; данные уничтожены автоматическим downgrade.** Учитывать WAL и использовать согласованный backup; восстановление проверять отдельно. Rollback приложения не равен откату схемы/данных.

Основание: [sqlite3 transactions, backup, thread safety](https://docs.python.org/3.12/library/sqlite3.html),
[SQLAlchemy Session](https://docs.sqlalchemy.org/en/20/orm/session_basics.html),
[relationship loading](https://docs.sqlalchemy.org/en/20/orm/queryguide/relationships.html),
[Alembic autogenerate](https://alembic.sqlalchemy.org/en/latest/autogenerate.html),
[проектные backup/rollback gates](../deploy/DELIVERY.md).

## 9. Платежи, outbox, результаты и повторное выполнение

Этот раздел — проектные инварианты, выведенные из существующей архитектуры;
он не меняет стоимость, правила оплаты или текущие права пользователей.

- **Цена, баланс, владелец или право на recompute берутся из клиента.** Источник решения — сервер; повторно проверять актуальные права, стоимость и допустимое состояние в момент выполнения.
- **Потеря дроби при преобразовании денег, отрицательное количество, переполнение диапазона БД.** Валидировать единицы и диапазоны до расчёта; сохранять целые копейки на всём пути.
- **Списание, результат и delivery status расходятся после сбоя.** Сохранять существующие границы транзакций, persisted outbox и recovery; не добавлять прямой путь отправки, обходящий их.
- **Timeout/обрыв объявлен доказанным провалом удалённой операции.** Сначала выяснить состояние по устойчивому ID, затем повторять/возмещать по контракту; неизвестный результат не равен отсутствию списания.
- **Дубликат webhook/upload/recompute применён повторно.** Использовать устойчивый idempotency key, DB-уникальность и атомарный переход; локальный флаг недостаточен при рестарте и нескольких workers.
- **Webhook считается достоверным только по JSON или адресу вызывающего.** Проверять подпись/достоверность по протоколу провайдера, сумму, валюту, связь с заказом и допустимый переход статуса.
- **ACK/outbox удалён до подтверждённой обработки, retry меняет ID операции.** Подтверждать после надёжной записи; повторная доставка должна использовать тот же ID и не дублировать эффект.
- **Локальный integer query ID смешан с control-plane UUID.** Соблюдать [контракт managed checks](managed-check-identifiers.md), не восстанавливать соответствие по тексту запроса или позиции.
- **Ошибка анализа превращена в платный успешный ответ; повтор запускается автоматически вопреки продукту.** Сохранять текущую политику failed/skipped, оплаты и ручного повтора; гонку upload/recompute проверять по состояниям.

Основание: [OWASP business logic](https://cheatsheetseries.owasp.org/cheatsheets/Business_Logic_Security_Cheat_Sheet.html),
[transaction authorization](https://cheatsheetseries.owasp.org/cheatsheets/Transaction_Authorization_Cheat_Sheet.html),
[managed IDs](managed-check-identifiers.md), [Coinso](coinso.md),
[PROJECT_STATE.md](../PROJECT_STATE.md). Выбор recovery/idempotency — проектное правило.

## 10. HTTP, внешние API и LLM

- **Нет сетевого timeout, либо один timeout считается дедлайном всей операции.** Задавать connect/read/write/pool timeouts и при необходимости общий дедлайн; `read` timeout ограничивает ожидание данных, а не полный объёмный download.
- **Безлимитные retries или одинаковый немедленный retry всех клиентов.** Ограничивать попытки и суммарное время, применять backoff/jitter и применимый `Retry-After`; различать transport retry и новый платный скан.
- **Retry любого POST без идемпотентности.** Учитывать возможность уже выполненного запроса; следовать разделу 9 и протоколу внешнего сервиса.
- **HTTP status, media type и JSON shape не проверены.** Проверять статус и контракт ответа; HTML страницы входа/лимита не принимать за JSON или ответ модели.
- **Полный `response.read()` недоверенного payload и неограниченный pool.** Ограничивать соединения, длину запроса/ответа и скачиваемого файла; контролировать реальное потоковое чтение, не только Content-Length.
- **TLS выключен «чтобы заработало», редиректы передают запрос не туда.** Использовать доверенный TLS, проверять конечный адрес и не переносить вручную Authorization на иной origin.
- **Ошибка одного провайдера стирает успехи других.** Соблюдать проектные независимые состояния сервисов; fail-fast выбирать только там, где это нужный контракт.
- **LLM-текст исполняется или сразу становится SQL/командой/финансовым решением.** Считать вывод недоверенными данными: schema/allowlist/лимиты; права, цены и состояние не отдавать модели на усмотрение.
- **Токен/cache/client привязан к «последнему пользователю» или к другому loop.** Область жизни должна учитывать аккаунт, секреты и thread/loop; не смешивать cookies и ответы клиентов.

Основание: [HTTPX timeouts](https://www.python-httpx.org/advanced/timeouts/),
[resource limits](https://www.python-httpx.org/advanced/resource-limits/),
[async client lifecycle](https://www.python-httpx.org/async/),
[input validation](https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html),
[business logic](https://cheatsheetseries.owasp.org/cheatsheets/Business_Logic_Security_Cheat_Sheet.html).

## 11. Недоверенные данные, права и безопасность

- **`eval`/`exec`, untrusted pickle/shelve/marshal или небезопасный YAML loader.** Передавать данные в проверяемом формате, не код; если появится YAML — безопасный loader с лимитами, без внедрения новой библиотеки заранее.
- **`os.system` или shell-string с пользовательским вводом.** Для обычного executable использовать `subprocess` с argv, без shell, проверкой returncode и timeout. На Windows `.bat/.cmd` имеют отдельную shell-семантику: не передавать им недоверенные аргументы по общему рецепту.
- **`random`, UUID или время как секретный token; самодельная криптография.** Использовать `secrets` и проектные security helpers; не заменять password KDF быстрым hash.
- **Секретная подпись сравнивается обычным `==`.** Использовать применимый constant-time helper (`hmac.compare_digest`) и проверенный протокол; не придумывать схему подписи.
- **Проверка доступа только в UI, «админ» по полю запроса, lookup по ID без ownership.** Проверять права на сервере для каждого объекта/операции; fail-closed, включая download/export, agent upload и служебные endpoints.
- **Localhost API считается автоматически защищённым от браузера.** Сохранять ограничения host/origin и механизм авторизации; не расширять bind/CORS без проверки доступа, CSRF и DNS rebinding.
- **CORS используется как авторизация; cookie-login меняет состояние без CSRF-защиты.** Использовать существующие меры, безопасные cookie/redirect/session defaults; новые endpoints не должны обходить их.
- **Произвольный URL скачивается сервером/агентом.** Для сетевой загрузки проверять схему, адрес назначения, приватные/loopback/link-local адреса и редиректы по политике; учитывать DNS rebinding, allowlist и сетевые ограничения, не только regex URL.
- **Входной путь, имя файла или archive member выходит за целевой каталог.** Запретить абсолютные пути, traversal и опасные ссылки; учитывать resolved path, Windows drive/UNC и symlink races.
- **Непроверенный HTML/Markdown или формула попадает в UI/экспорт.** Сохранять sanitization ссылок/HTML и безопасную запись текста в Excel/CSV; исходный ответ хранить отдельно от представления.
- **Безлимитные JSON/XML/regex/image/archive payloads.** Валидировать размер и сложность, не разрешать XML external entities; проверять распакованный размер и размеры изображения, не только расширение.
- **`.env`, токены, профили, дамп пользователя вошли в Git, debug route или сборку.** Следовать исключениям Git и упаковки; smoke-тесты использовать с изолированными данными.

## 12. Файлы, Windows, упаковка и обновления

- **Относительный путь зависит от текущего каталога или всё пишется рядом с EXE.** Использовать существующий `app/config.py`: source/frozen ресурсы, portable/installed user data и `%LOCALAPPDATA%` имеют разную семантику.
- **`sys._MEIPASS` принят за постоянный каталог данных.** Это ресурсный каталог сборки; пользовательские профили, DB и настройки хранить в DATA_DIR.
- **`exists`/`os.access` перед записью считается гарантией.** Обрабатывать реальную файловую операцию и `OSError`; учитывать TOCTOU, недоступный каталог и существующий файл.
- **Запись JSON/manifest прямо поверх рабочего файла.** Где важна целостность, писать временный файл на том же filesystem и атомарно заменять; atomic replace не гарантирует power-loss durability — при таком контракте нужны flush/fsync и recovery.
- **`mktemp`, предсказуемое временное имя или чужой файл открывается по этому имени.** Использовать `tempfile`; учитывать Windows reopen/delete semantics и закрытие handle перед заменой.
- **Архив без ограничений извлекается поверх приложения/данных.** Проверять каждый member, тип, пути, число и распакованный размер; для tar в Python 3.12 явно выбирать безопасный filter, дополненный проверками. У ZIP и tar разная семантика.
- **Checksum скачан из того же недоверенного места и назван доказательством подлинности.** Сохранять доверенный источник manifest/hash, TLS и имеющиеся проверки publisher/browser release; целостность не равна происхождению.
- **Обновление заменяет открытый EXE или удаляет профиль при ошибке.** Соблюдать update admission, завершение процесса, staging и rollback; заменять файлы программы отдельно от пользовательского состояния.
- **Одна manifest/ZIP/installer alias переключена раньше остальных.** Сохранять существующую атомарную публикацию полного релиза; не смешивать версии при повторе/обрыве.
- **После `PermissionError`/lock приложение «лечится» удалением DB/профиля.** Сохранять данные и сообщать ошибку; проверять file-lock, повторный запуск и недоступный путь на Windows.
- **Subprocess pipes оставлены заполниться, timeout не завершает дочерний процесс.** Использовать подходящий `run`/`communicate`, проверять код и lifecycle; отдельно учитывать дерево процессов и объём вывода.
- **Тесты проходят в source, поэтому frozen build считается проверенной.** Проверять нужный режим, пути с пробелами/кириллицей, ресурсы/hidden imports, пустой cache и сохранение старых user data.

## 13. Браузеры и сканирование провайдеров

- **Фиксированный sleep назван проверкой готовности.** Ожидать наблюдаемое состояние/locator/ответ с deadline; сохранять необходимые humanization delays, не удалять их механически.
- **`networkidle`, первый непустой DOM или один quiet interval доказывает конец генерации.** Использовать provider-specific completion признаки и общий timeout; quiet-time эвристику явно ограничивать и проверять на потоковом ответе.
- **Глобальная замена таймаутов без трассировки владельцев.** Использовать действующий профиль timing и [benchmark](scan-delays.md); проверять affected provider tests.
- **Один browser/page/profile параллельно используется независимыми сканами.** Соблюдать существующую модель владения и profile locks; разделять сервисы/аккаунты и освобождать ресурсы при cancel.
- **Длинный XPath/порядковый `nth` и `force=True` маскируют неправильную цель.** Выбирать устойчивые selectors и actionability; fallback должен отличать изменённый DOM от отсутствия ответа.
- **Извлекается весь текст страницы, включая чужие ответы/служебный UI.** Ограничивать область конкретным ответом и сохранять структуру, таблицы, цитаты и links по текущему контракту.
- **Login, CAPTCHA, rate-limit или provider error считается ответом бренда.** Выделять состояния и безопасную диагностику; не продолжать платный анализ ошибочной страницы.
- **Повторная отправка запроса после timeout без выяснения состояния.** Не дублировать генерацию/charge; соблюдать текущую ручную retry policy и cancellation.
- **Browser profile передаётся в артефакт, общий профиль сменяет аккаунт.** Использовать пользовательский профиль по назначению, не включать cookies в logs/build и не очищать его ради диагностического запуска.

Основание: [Playwright auto-waiting](https://playwright.dev/python/docs/actionability),
[Page: timeout/networkidle caveats](https://playwright.dev/python/docs/api/class-page),
[scan timing](scan-delays.md), [session preservation](session-preservation.md),
[answer capture](answer-readability.md). Completion и retry policy — решения AIRate.

## 14. Производительность и кэш

- **Оптимизация по догадке или полная переработка ради миллисекунд.** Сначала измерить конкретный поток, объём и bottleneck; использовать существующий benchmark/cProfile.
- **Вложенный поиск, повторная нормализация и SQL/HTTP в цикле.** При реальном объёме выбрать set/dict, batch или переиспользование вычисления; не менять порядок/точность ради ускорения.
- **Весь отчёт, image или response материализуется в память.** Использовать bounded iteration/streaming, где это оправдано; не добавлять generator без реального выигрыша.
- **Безлимитный `cache`, `lru_cache(maxsize=None)` или cache удерживает `self`/секрет.** Ограничивать память и lifetime; при account-dependent результате включать нужный scope и инвалидировать по контракту.
- **Кэшируется coroutine/генератор/побочный эффект.** Не оборачивать async function обычным `lru_cache`; кешировать только подходящие значения, не одноразовый объект или финансовую операцию.
- **Кэш принял на себя авторизацию или актуальную цену.** Проверять текущие права и quote по существующему серверному контракту; устаревший кэш не должен разрешать списание.
- **Ручной универсальный cache framework и параллелизм «на всякий случай».** Переиспользовать имеющееся; новая сложность нужна после измерения и с понятными eviction/ownership правилами.

Основание: [profiling](https://docs.python.org/3.12/library/profile.html),
[functools cache/lru_cache caveats](https://docs.python.org/3.12/library/functools.html),
[HTTPX pooling](https://www.python-httpx.org/advanced/clients/),
[проектный scan benchmark](scan-delays.md).

## 15. Типы, зависимости и совместимость

- **`Any`, `cast`, `type: ignore` скрывает несовпадение данных.** Описывать реально используемую форму; suppression ограничивать конкретной причиной, проверяемой на runtime-границе.
- **Структура словаря меняется от caller к caller.** Переиспользовать существующие DTO/schema/type; не создавать второй несовместимый контракт того же payload.
- **Приватный API библиотеки или Python-версия новее CI используется без проверки.** Предпочитать публичный API; workaround имеет version ceiling и targeted check, не рассчитывает на память о документации.
- **Непинованный upgrade ломает Playwright/Camoufox/PyInstaller.** Сохранять действующие constraints; обновлять намеренно с protocol/frozen/provider checks, не массовым `pip install -U`.
- **`pip freeze` с рабочего ПК принят за минимальные requirements.** Менять нужную зависимость в правильном файле, использовать venv/интерпретатор проекта; не включать случайные dev/Windows пакеты в сервер.
- **Linux и Windows считаются одинаковыми по file locking, spawn и путям.** Проверять платформу затронутого поведения; не устранять ошибку отключением проверки или изменением данных пользователя.
- **Автоматически включены все lint rules, mass-format и новый type checker.** Каталог не устанавливает инструменты и не создаёт массовые правки; при отдельной задаче выбирать полезные правила и постепенно устранять baseline.

Основание: [typing](https://docs.python.org/3.12/library/typing.html),
[virtual environments and packaging](https://packaging.python.org/en/latest/guides/installing-using-pip-and-virtual-environments/),
[Ruff rule catalogue](https://docs.astral.sh/ruff/rules/),
constraints в `requirements.txt`, `server/requirements.txt` и существующем CI.

## 16. Тесты и проверка поставки

- **Регрессионной проверки нет или она повторяет строку реализации.** Добавить/скорректировать минимальный проверяемый сценарий поведения, который ломается от исходного дефекта; использовать существующий pytest.
- **Только happy path для ветвления, parser или recovery.** Проверить релевантные границы: отсутствие/пустота, invalid input, exception/cancel, повтор или рестарт; не множить одинаковые тесты ради количества.
- **Реальные credentials, user DB, browser profile, сеть или платный LLM в обычном тесте.** Использовать временные данные и контролируемые внешние ответы; live checks запускать только отдельно и по их разрешённому сценарию.
- **Sleep и wall clock делают тест недетерминированным.** Управлять clock/waits/сигналами; concurrency-сценарий синхронизировать barrier/event с ограниченным ожиданием, не надеяться на порядок выполнения.
- **Monkeypatch не там, где имя используется, либо остаётся после теста.** Патчить точку lookup, восстанавливать окружение/глобалы через pytest helpers и закрывать thread-local DB resources.
- **Mock допускает невозможный ответ и проверяется лишь число вызовов.** Моделировать фактический контракт, проверять результат и состояние; для DB-инварианта использовать реальную соответствующую БД в нужном уровне проверки.
- **Тест зависит от порядка, общего кэша/loop/портов или скрывает flakiness retry-ем.** Изолировать состояние; найти причину нестабильности, не снимать meaningful assertion и не объявлять skip доказательством.
- **Пройденный локальный unit test назван production/live verification.** Различать подготовленное, опубликованное и проверенное; не заменять существующие CI, Windows smoke, backup/restore и independent/risk review gates.

Основание: [pytest monkeypatch](https://docs.pytest.org/en/stable/how-to/monkeypatch.html),
[flaky tests](https://docs.pytest.org/en/stable/explanation/flaky.html),
[проектные проверки](../AGENTS.md), [delivery gates](../deploy/DELIVERY.md).

## Короткая проверка перед PR

1. Проверены общий путь, callers, применимые разделы и сохранение контрактов.
2. Ошибка/отмена/повтор не создают ложный успех, двойную оплату или потерю данных.
3. Входы валидируются, ресурсы закрываются, ожидания и потребление ограничены.
4. Выполнены затронутые проверки, известные ограничения записаны в PR.
5. Для документации: `git diff --check` и существование локальных ссылок;
   application build и новые lint/test frameworks для такого изменения не нужны.
