# Динамика упоминаний и пересчёт ответов

Base: `origin/production` 33b8404; ветка `codex/mention-growth`, исходно чистая.
Запрос: исправить динамику и обозначение %, открыть пересчёт всем владельцам
проектов, добавить один день, период и произвольные даты.

## Приёмка

- 1 из 3 → 3 из 3 даёт 33,3% → 100%, +66,7% в строке и дашборде.
- Общая база: выбранные запросы × системы × даты проверок; фильтры одинаковы
  для обеих точек, пагинация не влияет на расчёт.
- `skipped` — отсутствие упоминания; сбои отдельно, без данных процент неизвестен.
- Попапы и карточки показывают %, без относительного роста в скобках.
- Обычный владелец проекта пересчитывает сохранённые ответы без feature flag.
- Выбор: с даты, один день, период, две даты, помесячно, произвольный набор дат.
- Календарь дашборда; quote и POST используют один отбор дат.
- Сохраняются права, стоимость 80 копеек за ответ, повторяемость оплаты,
  ответы вне выбора и снимки уже созданных запусков.
- Shared viewers, device sessions и чужие аккаунты не получают право пересчёта.

## Шаги и доказательства

1. `metric-red.log`, `metric-ui-red.log` воспроизводят старый знаменатель и
   обозначение; исправление в общем reporting и report-view.
2. Пересчёт: отдельный worktree; red/green API и UI, затем интеграция.
3. Независимые Sol review и Astra risk review; исправление подтверждённых дефектов.
4. Финальные pytest server с временным PostgreSQL, npm test/lint/build, browser
   smoke с синтетическими ответами и fake AI в desktop/narrow.
5. Diff, коммит, release pipeline и live SHA в пределах доступов.
