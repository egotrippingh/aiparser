# Пополнение через Coinso

Официальная документация: https://coinso.io/docs, схема: https://coinso.io/openapi.yaml.

## Настройка проекта

- Включить СБП и криптовалюту в одном проекте Coinso.
- URL вебхука: `https://airate.tech/api/v1/webhooks/coinso`.
- Успешная оплата: `https://airate.tech/cabinet/?payment=success#/topup`.
- Неуспешная оплата: `https://airate.tech/cabinet/?payment=failed#/topup`.
- Сохранить `COINSO_PROJECT_ID` и **Secret Key** в `/opt/airate/deploy/.env`, доступ 0600. API Key не заменяет Secret Key. В frontend, агент и GitHub эти значения не передаются.

Счёт создаётся сервером с уникальным `custom`, суммой в рублях и адресом возврата конкретного заказа. Пользователь выбирает банк или валюту/сеть на странице Coinso. Способы и пределы суммы запрашиваются из API; лимиты AIRate дополнительно ограничивают пополнение диапазоном 300–100 000 ₽.

Coinso может начислять дополнительную комиссию плательщику: итог к оплате на его странице отличается от суммы пополнения. AIRate предупреждает об этом до перехода. Размер комиссии не зашит в frontend; его показывает провайдер по действующим настройкам проекта и выбранному способу.

## Подтверждение

Подпись `X-Signature` проверяется как HMAC-SHA256 исходного тела с Secret Key. Затем сервер независимо получает `/payment/status`: сверяет `invoice_id`, `custom`, сумму RUB и статус `paid`. Для криптовалюты поле `currency` обозначает монету, но поле `amount` остаётся рублёвой суммой счёта. На баланс попадает вся сумма счёта; комиссия провайдера не вычитается из баланса пользователя.

Возврат браузера и содержимое вебхука сами по себе не подтверждают оплату. Блокировки кошелька/заказа и уникальная запись проводки защищают от повторного зачисления. Стандартная страница Coinso разрешает сменить способ оплаты: сохраняется фактически оплаченный способ.

Coinso не повторяет потерянные вебхуки. Фоновая сверка перебирает ожидающие счета порциями по 10, также статус уточняется при возврате в кабинет. Сверка сохраняет существующий планировщик сканов и останавливается при graceful shutdown.

## Проверка и включение реальных оплат

Для тестов включить тестовый режим проекта Coinso и `COINSO_ALLOW_TEST_PAYMENTS=true` на сервере. Создание тестовых счетов доступно только администратору. Успешная симуляция получает статус `test_paid`, **не создаёт проводку и не пополняет расходуемый баланс**. Счёт в процессе создания не может быть зачислен до сохранения признака тестового режима.

После проверки выключить тестовый режим в Coinso и установить `COINSO_ALLOW_TEST_PAYMENTS=false`. Пересоздать только web: `docker compose up -d --no-deps web`, проверить readiness. Старые тестовые счета остаются тестовыми. Реальную оплату выполняет пользователь через Coinso.
