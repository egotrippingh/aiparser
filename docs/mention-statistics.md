# Упоминаемость в веб-кабинете

Правило от 22 октября 2026 года: 100% — все возможные упоминания в выбранных
запросах и ИИ-системах. Для одного запроса за день база равна числу выбранных
ИИ-систем; для дашборда за день — числу запросов после фильтров × числу систем.
За период база умножается на число дат проверок; календарные дни без запусков
между ними не создают дополнительные измерения. При явном выборе дат
учитываются все выбранные даты. Пагинация не меняет базу.

Упоминаемость = `100 × found / total`. Динамика — разность долей без промежуточного
округления, отображаемая в `%` по принятому интерфейсному обозначению. Например,
1 из 3 → 3 из 3 означает 33,3% → 100%, изменение +66,7%. Это не относительный
рост +200%. В обычном режиме сравниваются первый и последний сканы периода;
в режиме двух дат — выбранные даты. База запросов и систем одинакова.

Отсутствие AI-блока (`skipped`) означает отсутствие упоминания. `checked`
включает `found`, `not_found`, `skipped`; `skipped` — подмножество `checked`.
`error`, `captcha`, `auth_required`, `limit_reached` сохраняются как отдельные
сбои, не превращаются в отрицательные результаты и не уменьшают базу `total`.
Если успешных проверок нет, процент и динамика неизвестны, а не равны нулю.
Полностью отсутствующий результат запроса на одной из дат не создаёт нулевой
точки для сравнения. Фильтры карточек и внешних источников меняют числитель.

Сводка, ИИ-системы, запросы, график, сравнения и XLSX используют общую базу.
История пересчитывается при чтении: записи, оплата и сохранённые ответы не
изменяются, повторный сбор не нужен. Legacy API `/api/v1/reports` и локальные
отчёты снятого с эксплуатации Windows-агента сохраняют прежний контракт.
