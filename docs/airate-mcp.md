# MCP для AIRate

MCP-сервер запускается на компьютере клиента через `stdio` и обращается к
публичному REST API AIRate по HTTPS. Для доступа он использует ключ аккаунта.
Права на проекты, запуск проверок и списания контролирует AIRate.

## Подключение

[Инструкция подключения](https://airate.tech/docs/mcp/) показывает настройки для семи
клиентов. Node.js 22 или новее запускает npm-пакет через `npx`. Сборка сайта кладёт
архив с версией в `web/assets/mcp/`. Версия берётся из [package.json](../integrations/mcp/package.json).
При следующем изменении файлов пакета повысьте версию, чтобы клиент получил новый архив.

Для запуска из исходников выполните `npm ci --prefix integrations/mcp`, передайте
ключ `AIRATE_API_KEY` из окружения и укажите в клиенте команду `node` с абсолютным
путём к [cli.mjs](../integrations/mcp/cli.mjs). Проверьте подключение вызовом `list_projects`.

## Инструменты

Успешный ответ каждого инструмента содержит поле `data` с ответом REST API.

| Задача | Инструменты |
| --- | --- |
| Проекты | `list_projects`, `get_project`, `create_project`, `update_project` |
| Запросы | `list_queries`, `add_query`, `delete_query` |
| Проверки | `get_scan_quote`, `launch_scan`, `list_runs`, `get_run`, `control_run` |
| Сохранённые ответы | `list_answers` |

`update_project` заменяет настройки, расписание и весь список запросов. Сначала
загрузите проект через `get_project`, сохраните актуальную `revision` и поля,
которые должны остаться, включая ID запросов и `device_id`.

Перед потенциально платным запуском запросите `get_scan_quote` и подтвердите
стоимость. В `launch_scan` передайте полученные `revision`, `provider_state` и
`free_scans_state`, а также новый `request_id` из 32 строчных шестнадцатеричных
символов. Если ответ потерялся, используйте те же поля и тот же `request_id` для
повтора. При конфликте из-за устаревшего расчёта запросите новую оценку.

В `list_answers` задайте обе даты включительно. Для следующей страницы передайте
`data.next_after_id` как `after_id`, сохранив прежние фильтры. Значение `null`
означает конец списка.

## Как обновлять MCP при изменении REST API

1. В том же PR для каждой новой, изменённой или удалённой операции
   `/api/v1/public/` обновите инструмент, описание и параметры в
   [адаптере](../integrations/mcp/server.mjs). Вызывайте только публичные REST-маршруты
   через общий HTTP-клиент. Для операций записи укажите их эффект в аннотациях.
   При несовместимом изменении укажите, что потребуется поменять клиентам MCP.
2. Обновите эту таблицу инструментов и
   [проверку контракта](../server/test_airate_mcp.py). Если публичную операцию
   сознательно оставляете за пределами MCP, запишите причину здесь и добавьте
   исключение по конкретной паре HTTP-метода и пути в проверке покрытия.
3. Выполните `npm ci --prefix integrations/mcp` и запустите
   `python -m pytest server/test_airate_mcp.py -q` в окружении с
   `scripts/requirements-ci.txt`. CI сверяет маршруты, пройденные через MCP,
   с публичными операциями в OpenAPI. После получения новой версии переподключите
   MCP в клиенте, чтобы он перечитал список и схемы инструментов.
