# Сервер кабинета

Отдельное FastAPI-приложение для пользователей, балансов, СБП/карт Coinso и
учёта платных проверок. Локальный API парсера на VPS не публикуется.

Новые проверки Google AI Overview и Яндекс Поиск с Алисой выполняются здесь через XMLRiver,
без компьютера пользователя. Задайте `AIPARSER_XMLRIVER_USER` и
`AIPARSER_XMLRIVER_KEY` в окружении сервера; регион фиксируется в задании.
Ответ сохраняется перед анализом, а в отчёте показывается его безопасная структура
с источниками и доступными товарными фото. ChatGPT, Perplexity и отдельный Gemini
собираются через Scrapeless (`SCRAPELESS_API_KEY`); все пять сервисов работают без ПК.
Для этих трёх сервисов страна сбора фиксируется как US, независимо от региона поиска.
Старые задания сохраняют
прежний способ выполнения. Процедура выкладки со сменой схемы:
[XMLRiver server release](../docs/xmlriver-cloud-release.md).

Миграция `20261012_provider_tasks` добавляет сохранённые задачи и общий для всех
пользователей/процессов лимит провайдера. Перед выкладкой выполняются обычные
backup/restore и migration-head проверки из `deploy/DELIVERY.md`.
Лимиты задаются `SCRAPELESS_CHATGPT_CONCURRENCY`, `SCRAPELESS_PERPLEXITY_CONCURRENCY`
(по 100) и `SCRAPELESS_GEMINI_CONCURRENCY` (100, максимум 100), а
`CLOUD_RUN_CONCURRENCY` — число одновременных запусков на процесс (4, максимум 8).
XMLRiver использует лимиты аккаунта; недоступный API лимитов даёт один слот.
На владельца одновременно выполняется один проект, чтобы его очередь проектов
не занимала всех исполнителей. Общие слоты делятся между активными пользователями.
HTTP-пул ограничен 32 соединениями, общий анализ — 20 вызовами на процесс.
Результат коммитится до анализа; перезапуск получает созданную задачу по её ID.
При временной ошибке запрос остаётся незавершённым и возобновляется через 30 секунд,
ошибка сбора не превращается в отрицательный результат или строку ошибки отчёта.
После трёх неудачных задач новые проверки автоматически повторяют сбор с интервалом
не менее 15 минут. Пустой завершённый ответ также перепроверяется, а не публикуется
как ошибка. Исчерпание бюджета анализа требует проверки оператора.
Неопределённый исход POST блокирует повторную отправку и сохраняет занятый слот:
без идемпотентности поставщика автоматическая повторная оплата небезопасна.
Истёкший результат с известным ID освобождает слот. В новых запусках через 15 минут
проверяется прежний ID; если результат всё ещё истёк, повторяется только этот запрос.
Поставщик может оплатить обе задачи, но пользователь оплачивает одну проверку.
Сбой отдельного запроса не блокирует остальные запросы сервиса. Старые запуски
сохраняют ограничения повторов и историю. Alice-only проект нужно пересохранить с новым
сервисом: его старое расписание не подменяется проверками Яндекса автоматически.

Раздел «Администрирование» показывает всех пользователей, баланс/резерв/доступно,
балансы поставщиков и ссылки на их кабинеты. Для `/credits` OpenRouter нужен
`OPENROUTER_MANAGEMENT_KEY`; без него пробуется обычный ключ, отказ явно отображается.
Credits Scrapeless и остаток подписки показаны отдельно, без ложного общего остатка.
API недоступен — значение «Недоступно», а не ноль. Ключи доступны только серверу.

## Запуск

1. Поднимите PostgreSQL на том же VPS, без внешнего доступа к порту базы.
2. Установите `server/requirements.txt` в отдельное окружение.
3. Задайте переменные из `.env.example` в окружении процесса. Файл с реальными
   ключами и паролями не коммитьте. `PUBLIC_BASE_URL` должен быть HTTPS-адресом.
   При запуске сервер применяет миграции Alembic. Старую схему он принимает
   только при точном совпадении таблиц и колонок; данные пользователей и балансов
   сохраняются. Если схема отличается, запуск остановится вместо её перезаписи.
4. Соберите фронтенд с `VITE_APP_URL=/cabinet/ npm run build` в `frontend/`.
5. Запустите `uvicorn server.app:app --host 127.0.0.1 --port 8000` за HTTPS-прокси.
6. В кабинете Coinso задайте webhook URL
   `https://ВАШ-ДОМЕН/api/v1/webhooks/coinso` и включите только нужные способы
   оплаты. Для проверки всей цепочки включите тестовый режим Coinso и
   `COINSO_ALLOW_TEST_PAYMENTS=true` только на тестовом сервере.

Для VPS есть шаблон `deploy/compose.yml` с PostgreSQL, приложением и Caddy.
Скопируйте `deploy/.env.example` в `deploy/.env`, задайте домен, случайный
пароль БД и ключи Coinso; затем в каталоге `deploy/` выполните
`docker compose up -d --build`. DNS домена должен указывать на VPS, порты
80/443 должны быть доступны. Перед сборкой образа соберите `web/` командой
`npm run build` в `frontend/` с `VITE_APP_URL=/cabinet/`.

## Вход через Яндекс ID

Создайте веб-приложение в [Яндекс OAuth](https://oauth.yandex.ru/client/new/id/).
Включите права `login:info` и `login:email`, а в Redirect URI укажите
`https://ВАШ-ДОМЕН/api/v1/auth/yandex/callback` точно, без лишнего слеша.
Задайте `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET` в `deploy/.env` и
перезапустите веб-сервис. `PUBLIC_BASE_URL` должен содержать тот же HTTPS-домен.
Без этих переменных кнопка в кабинете показана, но отключена.
При входе и привязке передаётся `force_confirm=yes`: Яндекс показывает подтверждение
доступа с возможностью выбрать нужный аккаунт, даже если доступ уже предоставлялся.
При первой регистрации Яндекс подтверждает email, после чего пользователь
обязательно создаёт пароль (не менее 12 символов). До завершения аккаунт и сессия
не создаются; ссылка завершения действует 10 минут. Существующий аккаунт Яндекса
сохраняет вход, а пароль можно добавить в разделе «Аккаунт и оплата».

## Восстановление пароля и защита входа

Для писем восстановления задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`,
`SMTP_USER`, `SMTP_PASSWORD`, `SMTP_SECURITY=starttls` (или `ssl` для порта
465). Нужен настоящий HTTPS-домен в `PUBLIC_BASE_URL`. Без SMTP вход по паролю
и через Яндекс работает; форма восстановления сообщает, что отправка ещё не
подключена, и не обещает письмо. Письмо содержит
одноразовую ссылку на 30 минут. После смены пароля все старые сессии и коды
подключения отзываются. Ответ на запрос письма одинаков для существующего и
несуществующего email. Пять неверных паролей для одного email или 30 с одного
IP блокируют вход на 15 минут; также ограничены регистрация и обмен кодов.
Адрес восстановления — email аккаунта: введённый при регистрации либо полученный
от Яндекса. Привязка Яндекса не заменяет email уже существующего аккаунта. SMTP
подключается указанными переменными после получения адреса/доступа к отправителю;
секреты хранятся только в серверном `.env`. При подготовке используются FakeMailer
и тестовые аккаунты, реальные письма не отправляются.

Промокоды в администрировании можно включать/отключать, ограничивать общим числом
аккаунтов и точным сроком. Пустой лимит/срок означает отсутствие ограничения.
Один аккаунт применяет код один раз. Сканов и начислений прошлых активаций
изменение условий не касается; повторная активация не начисляет сканы ещё раз.

## Вход из настольного агента

Первый запуск показывает вход даже с флагом `--background`. Доступны Яндекс,
вход на сайте и email с паролем. После нового входа компьютер подключается
автоматически без кода. Если на сайте уже открыт аккаунт, пользователь один раз
подтверждает подключение указанного ПК. Это не позволяет чужой ссылке незаметно
добавить компьютер к уже открытой сессии.

Кнопки «Открыть кабинет» и «Пополнить» получают одноразовую ссылку, действующую
60 секунд. Токен агента не попадает в адрес браузера. Ссылка проверяет действующее
подключение агента и обменивается на отдельную браузерную сессию на 30 дней:
HttpOnly cookie, SameSite=Lax, Secure при HTTPS. Браузерные изменяющие запросы
проверяют Origin и заголовок клиента; токены старых агентов продолжают работать.
Выход на сайте отзывает браузерную сессию, не отключая агент. Смена пароля отзывает
все сессии. Сессию, уже созданную в браузере, можно завершить выходом на сайте;
отзыв ПК запрещает выдачу и обмен новых ссылок этого агента.

Изменения требуют серверной миграции `20260927_browser_login` и новой сборки
агента. Миграция применяется штатно при запуске обновлённого сервера.

## Резервное копирование

В каталоге `deploy/` выполните `sh backup.sh`: он создаст PostgreSQL custom
archive в `backups/`, восстановит его в отдельную временную БД, проверит таблицы
и только после успешной проверки сохранит контрольную сумму SHA-256. Рабочую БД
сценарий не очищает. Для повторной проверки запустите
`sh verify-restore.sh backups/ИМЯ.dump`.

Настройте ежедневный запуск `backup.sh` через cron или systemd timer на VPS.
Каталог `deploy/backups/` исключён из Git и должен быть доступен только
администратору сервера; копия на том же VPS не защищает от потери VPS. Для
внешней копии создайте **отдельный закрытый** S3-бакет и сервисный аккаунт,
задайте `BACKUP_S3_BUCKET`, `BACKUP_ACCESS_KEY_ID`, `BACKUP_SECRET_ACCESS_KEY`
в `deploy/.env`. Сценарий отправит проверенный архив в `postgres/` и проверит
размер и хэш метаданных объекта. Настройте срок хранения бэкапов отдельно от
скриншотов и периодически проверяйте скачивание и восстановление внешней копии.

Сервер использует OAuth code + PKCE S256. Состояние входа действует 10 минут
и привязано к cookie браузера; код возврата не попадает в клиентский JavaScript.
После проверки профиля браузер получает одноразовый билет на 1 минуту во
фрагменте URL. Аккаунт определяется по ID Яндекса. Если email уже занят
аккаунтом с паролем, пользователь входит по паролю и нажимает «Привязать
Яндекс ID» в кабинете; совпадение email само по себе аккаунты не объединяет.
Для входа в настольный парсер без пароля пользователь создаёт в кабинете
одноразовый код подключения и вводит его на экране скана. Код действует
5 минут, после обмена на локально защищённую сессию сразу удаляется.

Сервер принимает пополнения в рублях. Он сверяет HMAC-подпись webhook, а затем
ещё раз спрашивает Coinso о статусе счёта, сумме, валюте и способе оплаты.
Повторный webhook не создаёт второе зачисление. Операции пишутся в журнал
`ledger_entries`; суммы хранятся в копейках. Владелец аккаунта видит баланс,
резервы, историю и платежи в `/cabinet/`.

По умолчанию цена проверки — 165 копеек, минимальное пополнение — 30000
копеек. Комиссия провайдера не вычитается из баланса клиента: она учитывается
в себестоимости. Расчёт с VPS, S3 и арбитром приведён в [PRICING.md](PRICING.md).

## Windows-агент и права владельца

Соберите агент на Windows командой
`powershell -File scripts/build-exe.ps1 -AccountUrl https://ВАШ-ДОМЕН`.
После самопроверки появятся датированный ZIP и `dist/AI-Mentions-Windows-latest.zip`.
Для локального сервера кнопка скачивания появляется автоматически. На VPS
загрузите последний ZIP в `deploy/downloads/AI-Mentions-Windows-latest.zip` и
перезапустите веб-контейнер. `GET /api/v1/agent-download` сообщает сайту,
доступна ли сборка. При обновлении агента заменяйте ZIP; папка исключена из Git.
В Windows-агенте вход находится в «Настройках»: в кабинете войдите через
Яндекс ID, откройте «Аккаунт», получите одноразовый код и введите его в агенте.
Если порт локальной версии для разработки (8756) уже занят, EXE использует
другой свободный локальный порт и открывает собственное окно.

Для бесплатных проверок владельца после регистрации через Яндекс ID выполните
`python -m server.grant_admin USER_ID --env-file server/.env` (локально) или
`DATABASE_URL=... python -m server.grant_admin USER_ID` на той базе, которую
использует веб-сервер. Скрипт требует точный ID пользователя и привязанный
Яндекс ID. Право хранится в БД; обычная цена не меняется. Администратор видит
безлимит в кабинете и агенте, а проверки резервируются и закрываются по нулевой
цене без движения средств. Вторая среда (например, VPS) имеет отдельную БД и
требует отдельного назначения права после создания аккаунта в ней.

`POST /api/v1/checks/reserve` резервирует средства за уникальные идентификаторы
проверок, `POST /api/v1/checks/{id}/complete` списывает деньги один раз за
`found` или `not_found`. Капча, ошибка, отсутствие ответа и лимит освобождают
резерв, если серверный анализ ещё не был выполнен. После серверного анализа
стоимость списывается при закрытии резерва. Повтор после сбоя может
зарезервировать тот же идентификатор вновь.

Настольный парсер подключается через `AIPARSER_ACCOUNT_URL` или файл
`account-url.txt` рядом с `start.bat`. Пользователь входит на экране скана;
токен хранится локально через Windows DPAPI. Если на VPS задан
`OPENROUTER_API_KEY`, основной анализ выполняет серверная модель
`qwen/qwen3.8-flash` с бюджетом reasoning 512 токенов. Только спорные результаты
(включая неуверенное отсутствие бренда) проверяет независимый
`deepseek/deepseek-v4-pro-0813` с effort `none`. Успешный анализ переиспользуется
при техническом повторе; денежного потолка на одну проверку нет. Выбор моделей задаётся на сервере через
`OPENROUTER_PRIMARY_MODEL` и `OPENROUTER_ARBITER_MODEL`; reasoning effort можно
переопределить через `OPENROUTER_PRIMARY_REASONING_EFFORT` и
`OPENROUTER_ARBITER_REASONING_EFFORT`. При пустых effort используются выбранные
настройки модели. `OPENROUTER_PRIMARY_MAX_OUTPUT_TOKENS` и
`OPENROUTER_ARBITER_MAX_OUTPUT_TOKENS` по умолчанию равны 1024 (включая reasoning);
для Qwen с бюджетом 512 output должен быть не меньше 1024. Провайдеры выбираются
по цене с сохранением fallback, без `max_price`; для DeepSeek исключены
непроверенные четырёхбитные варианты. Legacy-запрос арбитража со скриншотом
сохраняет изображение и использует Gemini 3.8 Flash: DeepSeek принимает только текст.
Сохранённые `.env` и установленный Compose могут переопределять новые defaults:
при выпуске нужно синхронно обновить их и проверить эффективные настройки. Ключ не передаётся
клиенту, а текст ответа и скриншот идут через VPS в OpenRouter. Без серверного
ключа LLM-анализ недоступен. Перед сканом приложение
резервирует стоимость запланированных пар «запрос × сервис», после сохранения
результата списывает плату за состоявшуюся проверку, а остаток освобождает.
При обрыве связи операции остаются в локальной очереди. Следующий запуск
сначала сверяет сохранённые результаты и отложенные операции, затем разрешает
новый скан. Карточки товаров включаются или выключаются в статистике
дашборда; это не меняет цену уже проведённой проверки.

Для Windows EXE на компьютере сборки установите
`scripts/requirements-build.txt` и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-exe.ps1 -AccountUrl https://ВАШ-ДОМЕН
```

Скрипт выдаёт папку с `AI-Mentions.exe` и ZIP для скачивания. Пользователь
распаковывает весь архив и запускает EXE без установки Python; при первом
запуске приложение скачивает Camoufox. В архив не входят локальная база,
скриншоты, cookie и ключи. Подписанный установщик и автообновления пока не
реализованы.

**До публичного запуска** нужны реальные домен, VPS, SMTP-отправитель и мерчант
Coinso, сквозной тест оплаты в его тестовом режиме, проверка расписания на
выбранные числа месяца и время пользователя и
внешнее хранилище резервных копий, а также проверка фискализации с продавцом.
Открытый исходный код настольного парсера позволяет
убрать локальную проверку оплаты; для коммерческого продукта требуется
серверная ценность либо закрытая клиентская часть.
