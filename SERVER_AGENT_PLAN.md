# Управление на сайте, выполнение на компьютерах

Реализовано 26.09.2026: серверные проекты, назначения компьютеров, очередь,
расписания и минимальное окно агента. Старые локальные данные сохраняются.

## До перехода

- Проекты, группы и запросы хранятся в SQLite на компьютере.
- `app/agent.py` выгружает результаты и запускает локальные проекты по расписанию.
- `server/models.py::ScanPreferences` хранит одно расписание на пользователя.
- Сервер регистрирует несколько устройств пользователя, но не назначает им проекты.
- Кабинет строит список проектов из результатов; ключ проекта — `device_id:local_project_id`.
- Поэтому перенос проекта на другой компьютер сейчас не сохраняет единую серверную идентичность проекта.

## Целевой пользовательский сценарий

1. Пользователь устанавливает агент и нажимает «Войти через браузер».
2. Сайт авторизует пользователя и подтверждает подключение конкретного компьютера.
3. Агент получает отдельную отзываемую сессию устройства. Пароль и серверные ключи в агент не передаются.
4. При необходимости пользователь входит в ИИ-сервисы в локальных браузерных профилях.
5. Агент работает в трее. На сайте пользователь создаёт проекты, загружает запросы по группам,
   выбирает системы, режим браузера, расписание и компьютер для проекта.
6. Нажатие «Запустить» на сайте ставит задание в серверную очередь выбранного компьютера.
7. Все результаты доступны через сайт независимо от компьютера, выполнившего проверку.

В агенте остаются состояние подключения, название компьютера, статус ИИ-сессий,
кнопки входа в ИИ-сервисы, решение капчи, локальная пауза, автозапуск,
краткий прогресс, баланс со временем обновления и кнопка «Открыть кабинет».
Настройка проектов и аналитика находятся на сайте.

## Проекты и устройства

Проект принадлежит рабочему пространству аккаунта. Устройство выполняет назначенные ему проекты.
Первая версия поддерживает одно назначенное устройство на проект; у устройства может быть много проектов.

Пример: один аккаунт, устройство A выполняет проекты 1 и 2, устройство B — 3 и 4.
Оба пользователя видят все четыре проекта на сайте. История не разделяется по устройствам.

Сразу предусматриваем рабочее пространство и членство пользователя в нём. Для первой версии
у владельца одно пространство; приглашения и роли сотрудников можно добавить позже.
Это позволит агентствам пользоваться отдельными входами сотрудников и общим балансом.

Перенос проекта меняет исполнителя, но не ID проекта, запросов и отчётов.
В первой версии перенос разрешён после завершения/остановки активной задачи.
Автоматический перенос при кратком обрыве связи не включаем: различаются ИИ-сессии,
регион, доступные системы и состояние ещё выполняющейся проверки.

## Серверные сущности

- Workspace / Membership: владелец, доступ к проектам и балансу.
- Project: UUID, пространство, бренд, алиасы, домены, регион, назначенное устройство, revision.
- QueryGroup / Query: серверные UUID, проект, текст, группа, активность, revision.
- Device / DeviceSession: пространство, имя, версия, heartbeat, возможности адаптеров,
  состояние входа по каждой системе, отзыв доступа. Идентификатор создаётся при установке,
  пользовательские данные не включаются в распространяемый ZIP.
- ProjectScanConfig / Schedule: системы, headless/headful, скорость, числа месяца,
  время и часовой пояс IANA, например Europe/Moscow. Настройки имеют revision.
- ScanRun: ручной/плановый запуск, снимок настроек и запросов, дата среза, прогресс.
- ScanTask: запрос × система × запуск; назначенное устройство, состояние, попытка,
  lease и версия владения задачей.
- Result: task ID, ответ, источники, виды упоминания, ошибки, фактическое устройство,
  регион и время. Скриншот — ссылка на приватный объект S3, срок хранения 90 дней.
- Ledger / Check: резервирование, подтверждение и освобождение суммы, привязанные
  к серверной проверке; существующие правила тарификации и административный безлимит сохраняются.

## Доставка заданий и защита от повторов

Агент делает исходящие HTTPS-запросы к серверу. Открывать порты на компьютере не требуется.
Сначала достаточно периодического запроса заданий/long polling и heartbeat примерно раз в 15–30 секунд.

Задачи выдаются атомарно из БД с ограниченным сроком владения (lease), который агент продлевает.
Одной проверке соответствует один серверный task ID и один ключ финансовой операции.
Повторная отправка результата не создаёт второй результат или второе списание.
После перезапуска агент повторяет доставку сохранённого результата, прежде чем делать запрос заново.

Истечение lease само по себе не гарантирует остановку браузера на старом компьютере.
Переназначение требует проверки статуса, версии владения и отклонения устаревших записей.
Точно однократное выполнение запроса внешним сайтом при сбое сети не гарантируется;
идемпотентность результата и финансовой операции обязательна.

Баланс проверяется и резервируется сервером при выдаче работы, а не локальным агентом.
Не удерживаем деньги неопределённо за выключенный компьютер. Отмена и истечение
резерва согласованы с состоянием задач; поступившие сохранённые результаты сверяются до освобождения.
Повторные попытки ИИ-анализа ограничены серверной политикой, ключи моделей остаются на сервере.

Локальная БД хранит кэш назначенных проектов, очередь полученных заданий и неотправленные результаты.
Сервер хранит основную версию настроек. Изменения во время скана применяются к следующему запуску,
текущий использует свой снимок. Агент принимает только определённые команды продукта,
а не произвольные команды ОС. Сессия устройства имеет доступ только к назначенной работе.

## Расписание и ограничения компьютеров

Планировщик работает на VPS. Дедупликация по проекту, расписанию и запланированному времени
не даёт двум серверным процессам создать одинаковый запуск. Расписание каждого проекта отдельно:
одно или несколько чисел месяца, выбранное время, часовой пояс. Несуществующее число месяца пропускается.

Если компьютер выключен, сайт показывает «Ожидает компьютер», резерв денег ещё не создаётся.
Политика пропуска: выполнить пропущенный запуск при подключении в течение 24 часов;
позже пометить его пропущенным и ждать следующей даты. Это правило показано в форме расписания.
Нельзя накапливать месяцы пропущенных запусков и исполнять их все при включении ПК.

В первой версии устройство сканирует один проект за раз, системы внутри него могут работать параллельно.
Два проекта не используют один браузерный профиль одной системы одновременно.
Авторизация в ИИ-сервисах и капчи остаются на компьютере. Сайт отображает, какому устройству
нужно действие пользователя. При сне ПК новые проверки не выполняются.

## Экраны сайта

- Проекты: общий список, группы/запросы, исполнитель, настройки и расписание.
- Проверки: запуск, пауза, остановка, очередь и прогресс каждой системы, причины ошибок.
- Отчёты: общая история проекта с любого устройства, сравнение срезов, переключатель учёта карточек.
- Компьютеры: имя, online/offline, назначенные проекты, доступные адаптеры и состояние ИИ-сессий,
  кнопки подключения и отзыва доступа.
- Баланс и аккаунт; позже — сотрудники и права доступа.

## Переход с текущей версии

1. Серверные проекты/запросы/назначения, права доступа и API. Текущий сборщик результатов ещё работает.
2. Управление проектами и запросами в кабинете. Создание проекта видно до первого результата.
3. Серверная очередь, расписания по проектам, аренда задач, идемпотентный биллинг и доставка результатов.
4. Агент получает только назначенные проекты, исполняет задания и отправляет статусы.
   Для мигрированных проектов локальный планировщик отключается, иначе будут двойные запуски.
5. Одноразовый импорт локальных проектов, групп, запросов и истории. Таблица соответствий
   `(account, device, local_project_id) -> project UUID`, также для запросов/результатов.
   Импорт повторяем без дубликатов. Не объединяем разные проекты автоматически лишь по совпадению домена.
6. Упрощённое окно агента, вход через браузер и обновлённая сборка EXE.

Проверка готовности: два независимых устройства под одним аккаунтом, разные назначенные проекты,
общий отчёт, выключение одного ПК, перезапуск во время скана, повторная отправка результата,
отзыв устройства, недостаточный баланс и смена часового пояса. Во всех сценариях должны
сохраняться уже полученные данные и отсутствовать повторные списания.

## Текущая реализация и обновление

- `server/control.py`: проекты, очередь, расписания, вход агента через браузер,
  права устройств, heartbeat и идемпотентные команды. Планировщик проверяет расписания каждые 15 секунд.
- `app/control_agent.py`: импорт локальных проектов один раз, получение назначений,
  выполнение неизменяемого снимка настроек и выгрузка результатов.
- Кабинет: проекты, запросы с группами и импортом TXT/CSV/TSV, настройки, расписания,
  проверки, общий отчёт, список компьютеров с переименованием и отзывом доступа.
- Трей: «Компьютер: <имя>», открытие агента/кабинета и выход. Имя Windows используется
  по умолчанию; переименование на сайте синхронизируется примерно за 15 секунд.
- Данные пользователя и профили браузеров не входят в распространяемый ZIP.

Перед обновлением сервера сохраните резервную копию БД. Миграция
`20260926_control` применяется при старте. Сначала обновите сервер, затем агент.
Для текущих локальных установок используйте тот же каталог `data`, предварительно
закрыв старый агент через трей. После подключения локальные проекты импортируются
в аккаунт; их расписания по умолчанию выключены, чтобы исключить неожиданные запуски.

Сервер ставит задания в очередь, агент проверяет её каждые 15 секунд. Пропадание
связи отображается отдельно; задача не передаётся самовольно другому ПК. Один ПК
исполняет один проект, выбранные ИИ-системы могут работать параллельно. Токен
устройства не даёт права менять проекты, платежи или назначения на сайте.

Проверены контракт двух устройств, изоляция аккаунтов, расписание и часовой пояс,
повторный запуск/heartbeat, отзыв и повторное подключение, неизменяемые запросы,
резервирование/подтверждение и общий отчёт. UI проверен на 1440 и 390 px, включая
создание проекта, группы, расписание и команды запуска/остановки на тестовом сервере.
Реальные проверки внешних ИИ в ходе обновления не запускались.

## Глубокая проверка источников

Поле «Глубокая проверка источников» убрано из формы проекта. Форма больше не отправляет
`deep_check_depth` при сохранении. Для заданий сайта агент принудительно использует
глубину 0. Старые локальные записи сохраняются, внутренний механизм оставлен для совместимости.
